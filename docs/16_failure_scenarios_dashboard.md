# 16 — Failure Scenarios & Dashboard (Day 14)

## 1. What this component does — Sections 20, 21, 23, 32

Two pieces:

- **Section 23 — 10 required failure scenarios**, each deliberately
  forced and proven to fail safely against this project's own Safety
  Rules (docs/01, S3/S4/S9).
- **Section 32 — dashboard**: a Streamlit app that displays all 8 named
  panels, reading only from results files Days 5-13 already produced.

## 2. Section 23's 10 cases, and what actually handles each one

8 of the 10 cases reuse real mechanisms built on Days 3, 8, 9, 10 and
11, unchanged. 2 needed genuinely new Day 14 engineering, because no
real code path in this project could organically produce them.

| Case | Mechanism | New today? |
|---|---|---|
| 1. AI extracts incorrect information | `mock_env/faults.py` MALFORMED_INPUT + `exceptions/detector.py` | No |
| 2. AI selects incorrect tool | `failure_scenarios/tool_contracts.py` + `wrong_tool_harness.py` | **Yes** |
| 3. AI has high confidence but is wrong | `failure_scenarios/calibration.py` + `risk/risk_model.py`'s hard override | **Yes** |
| 4. AI encounters missing information | `mock_env/faults.py` MISSING_INFORMATION + detector | No |
| 5. Tool returns malformed output | `mock_env/faults.py` TOOL_FAILURE + detector | No |
| 6. Human and AI disagree | `exceptions/disagreement.py` (D-054's synthetic-mismatch pattern) | No |
| 7. Workflow contains an exception | `mock_env/faults.py` API_TIMEOUT + detector | No |
| 8. Same request processed twice | `mock_env/resume_db.py`'s stateful duplicate check | No |
| 9. External action requires approval | `risk/risk_model.py`'s hard override + `exceptions/approval_gate.py` | No |
| 10. AI attempts a high-risk action | `risk/risk_model.py` + `approval_gate.py` | No |

**Case 2 — why it's a harness, not a reproduced bug.** This workflow's
action-to-tool mapping is fixed and 1:1 (`fetch_resume` always calls
`resume_db`, never anything else) — there is no real branch point
where the system chooses between tools, so no real code path could
organically select the wrong one. Rather than fabricate a fake bug,
`wrong_tool_harness.py` deliberately calls `ticket_system.create_ticket`
where `fetch_resume` should call `resume_db.fetch_resume`, and
`tool_contracts.py` (new) checks the result's shape against what
`fetch_resume` is supposed to produce. This also closes a real gap:
Section 20 asks the system to "validate inputs and outputs" of
whichever tool it selects, and nothing before today actually did that.

**Case 3 — two separate things, deliberately kept apart.**
`calibration.py` computes a real Expected Calibration Error from the
12-case dataset — but against `data/ground_truth.json`, not the human
demo policy, because the policy and the AI classifier share an author
(D-043) and so can't evaluate calibration on their own.
**Real result: ECE = 0.27 on 10 scored cases** (reported plainly, not
treated as tuned — S7). Separately, a synthetic case forces 0.95
confidence on a decision constructed to be wrong, on an
irreversible+external action, proving Section 22's hard override in
`risk_model.py` does not consult confidence at all for that class of
action — a confidently wrong AI still cannot act alone.

## 4. Dashboard (Section 32)

`dashboard/app.py` (Streamlit) + `dashboard/data_loader.py` (pure,
Streamlit-free data access — unit-tested on its own). Nine tabs: the 8
Section 32 asks for, by name, plus a 9th for Day 14's own failure
scenarios. A headline banner surfaces the Shadow Score and readiness
tier directly from `results/day13_readiness_assessment.json`, per Day
13's own closing note — nothing is recomputed in the UI layer.

Every "honest finding" from prior days is carried into the dashboard
rather than smoothed over: the Disagreements tab states plainly that
the real dataset has 0 disagreements (D-054) and explains why; the
Human corrections tab shows the `source="simulated_demo"` tag on every
row (D-057) instead of presenting them as real corrections; the
Workflow versions tab shows V4 as `reached=False` (D-058).

```
$ streamlit run dashboard/app.py
```

Verified headless (no `$DISPLAY` needed) with Streamlit's own
`AppTest` runner against the real result files — 0 exceptions, 0
warnings after fixing one deprecated argument.
